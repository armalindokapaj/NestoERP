# Push security

- **Credentials** are server environment secrets, never in Git: `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY` (the .p8, `\n` escaped), `APNS_BUNDLE_ID`, `APNS_ENVIRONMENT` (`sandbox` for TestFlight-debug builds, otherwise production), `FCM_SERVICE_ACCOUNT` (service-account JSON). `google-services.json` and `GoogleService-Info.plist` are git-ignored. `PUSH_PROVIDER` is `off` (default), `log` (development; records an attempt with no content) or `live`.
- **Payload** = `notificationId`, `eventType`, `path`, plus the OS text and badge. No access tokens, cookies, file URLs or record data. Tested: `apnsPayload` keys are exactly `aps, eventType, notificationId, path`; FCM `data` is `path, notificationId, eventType, badge`.
- **Path** is always `/notifications/{id}/open`; the client only follows an in-app absolute path (`safePushPath`), and the route authenticates and re-authorises.
- **Lock screen** text is decided by privacy class (notification-templates.md). Mention and comment bodies never leave the app. No notification actions (Approve, Reject, Complete) are registered; "Open" is the only interaction.
- **Tokens** are delivery credentials: stored only in `device_registrations`, never logged, never returned by any API, never put in a metric label. A token that moves to another person is re-parented, not duplicated; a dead token (APNs 410/BadDeviceToken, FCM UNREGISTERED) disables its device.
- **Sign-out, expiry, revocation, account switch:** the device row is tied to the session and cascades; queued deliveries survive as history with no device and are suppressed. A device re-registered by someone else fails the send-time `userId` check.
- **Demo:** the demo user switch is logout + login (C-01), so each demo login has its own session and device rows. `PUSH_PROVIDER=live` in any process where demo conveniences exist (`APP_ENV` development/test/demo) is downgraded to `log` (`effectivePushMode`), so an impersonated demo user never reaches a real phone. `PUSH_ALLOW_DEMO=true` is the explicit opt-out.
- **Metrics/telemetry** hold counts and ages only (`push_*` gauges and counters); no per-person read-speed analytics exist or are planned.
